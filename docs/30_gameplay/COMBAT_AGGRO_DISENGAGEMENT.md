# Underworld — Combat Aggro, Pursuit and Disengagement

Status: **LOCKED DIRECTION for Phase-7 awareness, pursuit and disengagement behavior; exact detection radii, search durations, territory sizes and boss-reset values remain OPEN**

This document complements [`COMBAT_FOUNDATION.md`](COMBAT_FOUNDATION.md), [`COMBAT_GROUP_PRESSURE.md`](COMBAT_GROUP_PRESSURE.md), [`COMBAT_HIT_RESOLUTION.md`](COMBAT_HIT_RESOLUTION.md), and [`COMBAT_RECOVERY.md`](COMBAT_RECOVERY.md). It defines how enemies notice, pursue, lose and disengage from targets in an open survival world without relying on abrupt invisible leash circles.

## 1. Awareness and combat engagement are separate

Enemy awareness should progress through readable world-facing states rather than jumping directly between `idle` and `full combat`.

```text
UNAWARE
-> target not detected

SUSPICIOUS / ALERT
-> something was seen / heard / communicated
-> enemy investigates or prepares

ENGAGED
-> valid combat target
-> enemy pursues and attacks according to its combat role

DISENGAGING
-> continued pursuit is no longer reasonable
-> enemy returns toward territory / normal behavior
```

These labels are gameplay-language concepts, not final implementation enum names.

## 2. Detection is grounded in the world

Enemy detection may depend on physically/perceptually meaningful information such as:

```text
sight / facing / distance
noise generated by player activity
damage received
nearby ally alarm
enemy-specific senses
```

The system should not give enemies omniscient knowledge of player inputs or position through walls without an authored reason.

Examples:

```text
player passes quietly nearby
-> may remain unnoticed

player sprints / fights / makes obvious noise nearby
-> easier to detect

player damages enemy
-> enemy knows it is under attack

nearby ally visibly reacts
-> group may become alerted
```

Exact vision cones, hearing ranges and propagation rules remain implementation/playtest work.

## 3. Pursuit must feel persistent but finite

Once engaged, an enemy should pursue far enough that taking a few steps backward does not reset the encounter.

```text
enemy engages target
-> pursue while target remains reasonably reachable
-> tolerate short line-of-sight breaks
-> search / reposition if target disappears
-> reassess when distance, time or territory pressure grows
```

The project should avoid the obvious MMO-style behavior:

```text
cross invisible radius
-> enemy instantly turns around
-> forgets player
-> immediately restores full health
```

Disengagement should instead be a gradual decision based on lost contact, increasing separation, territory, pathability and enemy-specific behavior.

## 4. Disengagement is a transition, not an instant reset

When the player genuinely escapes:

```text
target contact is lost
-> enemy continues pursuit / search for a while
-> willingness to pursue decreases
-> enemy gives up
-> enemy returns toward home / patrol / encounter area
-> normal behavior resumes
```

An enemy returning home is not harmless by definition. If attacked again, it may re-engage when the circumstances still make sense.

The exact return-home behavior and health-recovery policy remain open, but ordinary enemies should not visually pop back to full health the instant pursuit ends.

## 5. Territory matters without becoming an invisible hard wall

Enemies may have a home territory, patrol region, lair, encounter origin or other authored area that influences pursuit willingness.

Territory is a pressure on the decision to continue chasing, not necessarily a binary circle that forces an immediate turn-around.

Different archetypes may have different persistence:

```text
territorial creature
-> reluctant to leave home area

predator / hunter
-> willing to pursue farther

defender / guard
-> prioritizes protected location

boss
-> strongly tied to authored encounter territory
```

Exact territory semantics remain content and implementation work.

## 6. Bosses may use stronger reset rules

Bosses require stronger encounter boundaries than ordinary enemies because unrestricted dragging can break encounter geometry, pathing, other world systems or intended challenge.

```text
boss engaged
-> pursues within reasonable encounter space

player truly leaves encounter
-> boss disengages
-> boss returns / recovers through authored encounter rules
```

A boss may therefore use a stronger reset than an ordinary creature. That reset should still be readable where possible and should avoid unnecessary teleportation except as a recovery/failsafe mechanism for broken navigation or encounter state.

Exact boss return behavior, health restoration, arena boundaries and re-engagement rules remain open.

## 7. Unreachable terrain must fail gracefully

A player gaining terrain advantage is not automatically an exploit. If a creature physically cannot reach a location, that can sometimes be legitimate survival gameplay.

The AI should nevertheless avoid obviously broken behavior:

```text
player reaches awkward terrain
-> enemy checks viable path / alternate approach
-> repositions where useful
-> uses ranged / alternate behavior only if that archetype actually has it
-> eventually disengages if target is genuinely unreachable
```

The system must not invent magical ranged attacks or immunity solely because a melee enemy cannot path to the player.

## 8. World entities may interact during pursuit

Pulling one hostile creature into another group should remain possible as emergent survival gameplay.

```text
player attracts enemy A
-> moves toward creature/group B
-> faction / hostility rules decide what happens
```

Possible authored outcomes include fighting, mutual indifference or cooperation. The combat system should not add a blanket anti-kiting rule that prevents world factions and creatures from interacting.

Exact faction relationships and aggro propagation belong to world/enemy content rather than this combat foundation.

## 9. Ranged kiting should be answered through behavior, not hidden immunity

A player using ranged attacks while retreating should face appropriate enemy behavior:

```text
enemy may sprint / charge / flank
-> may seek a better route or cover where authored
-> may continue pursuit while contact remains reasonable
-> eventually disengages when the player genuinely escapes
```

The project should not make an enemy magically immune to ranged damage merely because it has travelled too far from its spawn point.

## 10. High-level state flow

```text
DETECTION
   |
   v
ENGAGEMENT
   |
   v
PURSUIT
   |
   +-> target maintained? -> yes -> continue combat
   |
   v
SEARCH / REASSESS
   |
   +-> pursuit still reasonable? -> yes -> continue search / pursue
   |
   v
DISENGAGE
   |
   v
RETURN / RECOVER
```

The exact state-machine implementation is not prescribed here. The required product behavior is readable, world-grounded pursuit that is persistent enough to matter but finite enough to support an open survival world.

## 11. Explicitly open

The following remain implementation/playtest decisions:

- exact detection radii, vision cones and hearing ranges;
- exact suspicious/alert timing;
- exact ally-alert propagation;
- exact pursuit distance and persistence;
- exact search duration and search movement;
- exact home/territory radius or shape;
- exact disengagement scoring/thresholds;
- exact ordinary-enemy health recovery after disengagement;
- exact boss reset and health-restoration behavior;
- exact unreachable-target/pathing fallback behavior;
- exact faction hostility and cross-aggro rules;
- exact ranged-kiting counter behaviors;
- multiplayer threat/target-switching behavior.

Do not infer arbitrary numerical leash values from genre convention. Phase 7 requires readable awareness, pursuit and disengagement that remain grounded in world geometry and enemy identity.
